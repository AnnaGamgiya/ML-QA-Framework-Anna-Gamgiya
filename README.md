ML QA Framework
ML QA Framework — прототип универсального QA-framework для автоматизированного тестирования готовых ML-моделей.
Framework предназначен для готовых обученных моделей для табличных данных со sklearn-совместимым интерфейсом. Поддерживаются fitted estimators и sklearn Pipeline, бинарная и многоклассовая классификация, а также применимые проверки для single-output regression.
Для выполнения проверок используются стандартные возможности модели: predict(), predict_proba(), classes_, feature_names_in_.
Идея
Framework строит проверки по схеме:
Contract → Check → ValidationResult
Формальные требования собираются в контракт модели. Каждый check использует конкретное требование и возвращает структурированный результат проверки.
Источниками требований являются:
- model_metadata.json — machine-readable документация модели;
- формальный API загруженной модели.
Каждый результат содержит статус проверки, ожидаемое и фактическое значение, источник требования и технические доказательства результата.
Используются четыре статуса:
- PASS — требование выполнено;
- FAIL — требование нарушено;
- WARN — обнаружено техническое несоответствие;
- SKIP — для выполнения проверки недостаточно необходимых данных или возможностей модели.
Что нужно для запуска
Модель — обученный артефакт в формате .joblib.
Тестовый датасет — .parquet или .csv.
Metadata — файл model_metadata.json с формальными требованиями к модели.
Target тестового датасета — .csv, опционально. Используется для воспроизведения документированных метрик.
model_metadata.json
Metadata содержит machine-readable описание требований, необходимых framework для проверок.
В текущей версии используются:
- numeric_features — числовые признаки;
- categorical_features — категориальные признаки;
- target — целевая переменная;
- test_metrics_shipped — значения метрик, зафиксированные для тестового набора;
- library_versions — версии библиотек, использованные при сохранении модели.
Автоматические проверки работают со структурированным model_metadata.json и формальным API модели.
Проверки
1. Input Data
Проверяется структура тестового датасета:
- наличие обязательных признаков;
- отсутствие повторяющихся столбцов;
- соответствие списка признаков metadata и feature_names_in_ модели, если атрибут доступен.
2. Prediction Execution
Выполняется предсказание на загруженном тестовом датасете и проверяется успешность выполнения inference.
3. Prediction Output
Проверяется структура результата предсказания.
Для классификации проверяются количество предсказаний, допустимые классы, структура predict_proba, конечность вероятностей, диапазон [0, 1] и сумма вероятностей по строке.
4. Documented Metrics
При наличии target пересчитываются документированные метрики и сравниваются со значениями из metadata.
В текущей версии поддерживаются:
- ROC-AUC;
- PR-AUC;
- Brier score.
5. Environment Compatibility
Версии scikit-learn, pandas и numpy из metadata сравниваются с версиями текущего окружения.
Совпадение даёт PASS, различие версий — WARN.
Demo: Olist Delivery Risk
В examples/olist/ находится демонстрационный пакет для проверки framework.
Olist Delivery Risk — готовая модель бинарной классификации для табличных данных. В документации модели она обозначена как Gradient Boosting с isotonic calibration через CalibratedClassifierCV.
Артефакт содержит полный sklearn pipeline: preprocessing, classifier и calibrator.
Target: is_late.
Классы: 0 и 1.
Модель и связанные материалы доступны на Hugging Face:
https://huggingface.co/samuelalex37/olist-delivery-risk-model
Запуск
pip install -r requirements.txt

streamlit run app.py

После запуска в интерфейс загружаются модель, тестовый датасет, metadata и, при необходимости проверки метрик, target.

app.py

    contract.py
    runner.py
    result.py
    checks/

    olist/

mlqa/ — CORE framework.
mlqa/checks/ — пять автоматизированных проверок.
tests/ — unit-тесты.
examples/olist/ — демонстрационный пакет.
app.py — Streamlit-интерфейс.
